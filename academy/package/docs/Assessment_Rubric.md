# Assessment rubric

## Grade distribution
- Weekly quizzes: 15%
- Mathematical assignments: 15%
- Python practicals: 20%
- Q# practicals: 15%
- Algorithm implementation: 15%
- Capstone: 20%

## Coding rubric (Python and Q#)
| Criterion | Weight | Excellent | Satisfactory | Needs improvement |
|---|---:|---|---|---|
| Correctness | 35% | Correct, handles edge cases | Minor issues | Core logic incorrect |
| Mathematical understanding | 20% | Explains derivation and assumptions | Partial explanation | Cannot explain method |
| Code quality | 15% | Clear, modular, documented | Understandable | Difficult to reproduce |
| Validation | 15% | Tests and numerical checks | Basic checks | No meaningful validation |
| Interpretation | 15% | Correct scientific interpretation | Mostly correct | Overclaims or misreads results |

## Capstone rubric
Problem formulation 15%; mathematical foundation 15%; algorithm selection 15%; Python implementation 15%; Q# implementation 10%; validation and benchmarking 15%; scientific interpretation 10%; presentation and documentation 5%.

## Grading safeguards
- For stochastic outputs, assess distributions with tolerances, not exact counts.
- Require a classical baseline for application projects.
- Award no advantage claims without a justified complexity/resource analysis.
- Review code originality and require a short oral or recorded explanation for high-stakes assessment.
